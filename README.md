# Sea 云文档协作平台 · 产品 Demo

一个**可交互**的在线文档协作产品原型：文档编辑、划词评论、全局评论、版本历史、文件管理与账号体系。

> 🚀 **在线体验：https://w-yuzhe.github.io/sea-docs-demo/**
> 推荐 Chrome / Edge 打开，无需安装、无需登录即可体验。

---

## 这是什么

面向团队协作场景的在线文档协作平台原型。我用它完整走了一遍产品经理的日常链路：

**需求拆解 → 功能清单 → 业务流程图 → 原型 → 高保真实现 → 验收回归**

目的是验证每个模块的流程闭环与异常边界是否站得住，而不是做一个能上线的系统。

- 纯前端原型，**无后端、无真实服务**，所有数据存在浏览器 localStorage
- 个人产品实践项目
- 用于展示产品设计与交互落地能力

## 功能模块

| 模块 | 关键设计 |
|---|---|
| 首页 · 文件管理 | 列表 / 宫格双视图、类型与状态筛选、关键字搜索、单选与多选批量操作 |
| 文档编辑器 | 富文本编辑、行类型切换、封面与图标、目录大纲、划词评论 |
| 划词评论 | 选中正文即可发起评论，卡片锚定被选中的原文，支持回复 / 点赞 / 编辑 / 删除 |
| 全局评论 | 文档级讨论区，支持锁定时长、@ 提及、意见反馈入口 |
| 历史记录（版本时光机） | 时间轴回溯版本、版本对比、恢复与下载 |
| 文件管理后台 | 文件状态机：正常 → 回收站 → 已彻底删除 → 已销毁（30 天保留 + 90 天销毁宽限） |
| 账号体系 | 登录 / 注册 / 忘记密码，手机号与验证码校验、密码强度规则 |
| 意见反馈 | 反馈类型、功能模块、描述与截图上传，本地留存 |

## 我在这个项目里负责的

- **需求与 PRD**：拆解「编辑 / 评论 / 历史 / 回收 / 权限」五大场景，独立完成历史记录模块 PRD（功能概述、流程图、原型图三部分），明确数据结构、接口契约与边界异常处理
- **流程与交互**：定义文件状态机与「恢复 / 彻底删除 / 销毁」在单选、多选下的可用性规则；设计账号链路的交互与异常边界
- **异常与容错**：验证码失效、手机号已注册、格式校验等场景的提示设计（可在演示助手里逐个触发）
- **推进与验收**：以高保真原型驱动实现，并建立自动化回归用例保障迭代质量

## 目录结构

```
index.html               首页（文件管理 + 账号体系），自包含单页
editor.html              文档编辑器
editor.css / editor.js
common.css / common.js   公共样式与数据层（Store / 封面图库）
local-comments.js        划词评论
global-comments.*        全局评论（含独立演示页 global-comments.html）
history.js               历史记录 / 版本时光机
history-time.*           时间轴与版本时间展示
download.*               下载导出弹窗
sidebar-nav.js           侧边导航
```

## 说明

- 这是一个**产品原型**，不是生产系统：没有真实服务端，刷新或换浏览器数据会重置
- 为了演示方便，界面上保留了「演示助手」入口，用来快速填账号和触发各类异常提示
- 验证码固定为 `123456`，不会真的发短信
